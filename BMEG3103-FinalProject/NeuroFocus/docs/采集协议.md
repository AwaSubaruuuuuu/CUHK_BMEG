# 数据采集协议（操作者版）

> 目的：采集"静息（label 0）"与"心算（label 1）"两种状态的单通道脑电，
> 用于训练与评估专注度分类器。
> 一次完整采集约 7 分钟；**同一位被试建议做 2 次，中间休息 ≥10 分钟**。

---

## 0. 采集前检查（2 分钟）

| 检查项 | 做法 |
| --- | --- |
| 设备电量 | 开机后指示灯正常闪烁；电量低会导致掉包 |
| 接收器 | 蓝牙接收器插在电脑 USB 口，设备管理器 → 端口 中出现 `COMx` |
| 端口号 | 与程序里的端口一致（默认 `COM7`） |
| 程序 | `python main.py` 能打开；第 ① 页能选到端口 |
| 电极 | 头带电极干净、导电胶/电极片未干；耳夹弹簧正常 |
| 被试 | 已被告知流程，同意采集；采集前 30 分钟未喝咖啡/浓茶，未剧烈运动 |

## 1. 佩戴（3 分钟）

1. **擦皮肤**：用湿纸巾擦拭左前额（眉毛上方约 2 cm）和左耳垂后面的皮肤，
   去掉油脂与死皮，等皮肤自然干。
2. **贴电极**：把采集电极贴在**左前额、眉毛上方约 2 cm**处（FP1），
   轻压 10 秒让电极贴合。
3. **夹耳夹**：参考电极与接地共用一个耳夹，夹在**左耳垂根部**（不是耳廓上缘），
   夹紧但不要夹痛。
4. **整理线缆**：线从耳后绕到颈后，避免垂在脸前（会被眨眼/说话拉动）。

## 2. 检查信号质量（1 分钟）

打开程序第 ① 页，连上端口，观察：

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| `Signal` = 0，稳定 | 最佳 | 开始采集 |
| `Signal` 在 0–100 之间小幅波动 | 尚可 | 等 1 分钟让它稳定 |
| `Signal` 长期 > 100 或满格 | 接触不良 | 重新擦皮肤、压紧电极、调整耳夹位置 |
| 原始波形是一条直线 | 没收到小包 | 检查端口/设备是否开机 |
| 原始波形幅度非常大、毛刺密集 | 肌电/运动 | 让被试放松面部与颈部 |

> 判断标准：连续 30 秒内 `Signal` 基本为 0，且 attention 有正常波动（不是恒定的 0 或 100）。

## 3. 采集流程（6 × 60 s）

被试坐姿舒适，双手放在腿上，**全程闭眼**：不睁眼看屏幕、不说话、不吞咽、不动手。
两种状态只差"脑子里在不在算"：

| 段 | 时长 | 任务 | 标签 | 操作者要点 |
| --- | --- | --- | --- | --- |
| 1 | 60 s | **静息**：闭眼、放松、不刻意思考 | 0 | 确认被试闭眼、面部放松 |
| 2 | 60 s | **心算**：闭眼从 1000 连续减 7，默算 | 1 | 段末问一句"算到几了"，填进报数框 |
| 3 | 60 s | 静息 | 0 | 同第 1 段 |
| 4 | 60 s | **心算**：接着上一段的数继续减 | 1 | 再次记录报数 |
| 5 | 60 s | 静息 | 0 | 同第 1 段 |
| 6 | 60 s | **心算**：同上 | 1 | 保持负荷，算错也没关系 |

推荐直接用图形界面采集（**被试不需要看屏幕、不需要敲键盘**，界面只给操作者看）：

```bash
python main.py
# 进入「① 设备与信号」连接 COM7 → 「② 采集与标注」填被试编号 → 开始采集
```

也可以命令行采集（文字与提示音引导，被试全程不碰电脑）：

```bash
python main.py --record --port COM7 --subject S01 --blocks 6 --block-sec 60
```

程序按上表顺序提示（提示音：静息 440 Hz，心算 880 Hz）。

### 3.1 心算任务：闭眼从 1000 连续减 7

- 心算段开始时，界面只显示一行大字 `1000 − 7` 和一句提示，供**操作者**确认当前状态；
  被试闭着眼默算，**不读题、不输入**；
- 被试从 1000 起连续减 7（1000 → 993 → 986 …），减到负数继续减，中途不要停在某个数上；
- 心算段结束时（或紧接着的静息段里），操作者问一句"算到几了"，把数字填进
  "段末记录报数（选填）"框、按回车即可；
- 报数写进同名 `*_tasks.csv`（`t,qid,question,answer,result`；`result` 固定 -1 表示不计分），
  **只作行为证据，绝不作为模型输入**；
- 静息段界面显示"闭眼静息"，提示语换成"放松、不要思考题目"。

**为什么改成闭眼默算**：这是本项目协议的第三次迭代。第一版被试出声报数 → 说话肌电；
第二版屏幕出题、敲键盘作答 → 读题带来眼动与眨眼、敲键盘带来手部肌电。
这两类成分在额极 FP1 上比"专注"本身强得多：用第二版采到的真实数据实测，
`raw_max` 单特征 AUC 就有 **0.936**、`raw_std` **0.913**；只用 `raw_std` 取中位数阈值，
在两个留出折上就能拿到 0.988 / 0.965。也就是说分类器完全可能学的是"睁眼 + 打字"。
改成闭眼默算后，两种状态都闭眼、都不动手，眼动与肌电在两类之间基本对齐，
剩下的差异才更接近认知负荷。

> 代价：没有逐题判分，行为校验变粗（只能看报数是否合理、被试是否肯报）。
> 这是有意的取舍——宁可少一个指标，也不把手眼运动混进"专注"的标签里。

**段间不停顿**：一段结束后立即开始下一段（程序自动切换提示音），
但每段前 **10 秒**的数据会在分析时丢弃（任务切换的适应期），这一点程序已自动处理。

## 4. 采集后

1. 程序会在 `data/raw/` 下生成 `S01_20261109_193000.csv`（文件名 = 被试_时间）；
2. 同目录还有 `S01_20261109_193000_tasks.csv`（每段心算的报数，用于核对这一段是否真的在算）
   和 `S01_20261109_193000_quality.txt`（采集结束时的自动体检，见下）；
3. **先看体检结论**：程序在采集结束那一刻比较两类状态的幅度与 highAlpha——
   - 通过：两类幅度与 alpha 基本对齐，可以入库；
   - 告警（alpha 掉到 0.7 以下且幅度涨到 1.5 倍以上）：疑似睁眼/眨眼/眼动，**这段不要入库**，
     确认被试全程闭眼（必要时加眼罩）后重采；
   - 告警（只是幅度差 1.5 倍以上）：可能有咬牙、点头、说话或手部动作，让被试放松下颌后重采；
4. 打开 CSV 检查：行数应约等于总秒数（6 × 60 = 360 行，允许 ±5 行丢包）；
5. 在程序第 ③ 页勾选该文件 → **构建数据集** → 查看"丢弃样本数"是否异常
   （正常丢弃 < 20%，若超过 30% 说明信号质量差，建议重采）；
6. 让被试休息 10 分钟后可进行第二次采集（文件名会不同，自动区分）。

> `*_tasks.csv` 不会被列进数据集文件列表，也不会被 `--train` 读入——
> 它只有报数与题面文字，没有 EEG 列，混进数据集会把文字当成脑电行。
> `*_quality.txt` 同理：`.txt` 不在采集文件通配范围内。

**为什么要有这道体检**：单通道 FP1 上，眨眼/眼动/咬牙的幅度可以是"专注"本身的好几倍。
本项目的第二版协议（心算时看屏幕 + 敲键盘）采到的真实数据里，`raw_std` 与 `raw_max`
的静息/心算比值就到了 2.6 / 2.4，单特征 AUC 0.99——模型完全可能学会"睁着眼打字"而不是"专注"。
体检不改变数据，只在采集结束的那一刻把这件事说出来，避免把可疑数据带进训练。

## 5. 常见问题

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 打开端口失败 `拒绝访问` | 端口被别的程序占用 | 关闭串口助手/另一个程序实例 |
| `无法打开 COM7` | 端口号错/接收器没插 | 设备管理器确认端口号，改 `--port` |
| 12 秒没收到数据 | 设备没开机或没配对 | 长按开机键，确认指示灯 |
| 数据里 attention 一直是 0 | 设备还在预热/接触不良 | 等 1–2 分钟，检查 Signal |
| 行数明显少于 360 | 蓝牙丢包 | 靠近电脑、避开 USB 3.0 干扰源 |
| 体检告警"疑似睁眼/眨眼/眼动" | 心算段睁眼了，或被试在想题时频繁眨眼 | 加眼罩、让被试把手放在腿上，重采这一段 |
| 体检告警"幅度相差较大" | 咬牙、点头、说话、手上用力 | 提醒放松下颌与肩颈，两种状态姿势保持一致 |
| 心算段大字还是「闭眼静息」 | 还停在静息段（第 1/3/5 段） | 等进入「心算 FOCUS」，大字会变成 1000 − 7 |
| 报数框敲不进去 | 还没开始采集 | 点「开始采集」后自动启用 |
| 忘了记报数 | 常见 | 不影响建模，日志里记一笔「未报」即可，下一段补记 |
| 采集到一半被试打喷嚏/说话 | 伪迹 | 该段标记为噪声（在文件名加 `_bad`），分析时排除 |

## 6. 伦理与记录
