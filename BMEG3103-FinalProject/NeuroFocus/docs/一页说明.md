# NeuroFocus —— 一页说明

**一句话**：用一个通道的脑电（FP1）判断此刻是否在专注，再用一个 3 061 参数的小网络
在普通电脑上实时给出 0–100 的专注概率；真实数据两折交叉验证 **Accuracy 0.890**。

---

## 1. 系统示意图

```
   TGAM 头带（FP1 + 左耳参考）
            │ 蓝牙
   蓝牙接收器 ──USB──► COM7 @57600
            │
            ▼
   ┌──────────────────────────────────────────────────────┐
   │ ① 解析：AA AA len … checksum                          │
   │    1 Hz 大包 → signal / attention / 8 段功率          │
   │    512 Hz 小包 → raw_std / raw_max（伪迹）            │
   │ ② 清洗：前 10 s 丢弃、"没戴好"码丢弃、伪迹窗丢弃       │
   │ ③ 组窗：最近 8 秒 × 12 特征 = 8×12 的小矩阵           │
   │ ④ 推理：Conv1D(16,k3)→Conv1D(20,k3)→Conv1D(24,k3)     │
   │          →GAP→Dense→sigmoid  = 3 061 参数              │
   └──────────────────────────────────────────────────────┘
            │
            ▼
   P(专注) → 实时仪表 / 曲线 / 阈值报警
```

数据流：**512 Hz 字节流 → 1 Hz 特征行 → 8 秒滑动窗口 → 一个概率**。
标签只来自实验协议（静息 = 0，心算 = 1），绝不使用设备的 attention 当标签。

## 2. 模型论证

**为什么是 1-D CNN（3 层）？**

| 方案 | 参数量 | 优点 | 致命问题 |
| --- | --- | --- | --- |
| 阈值法（attention 均值 > 75，brief Option A） | 0 | 零算力 | 每折只有 0.62，阈值要人手调，误报集中 |
| 全连接（96→64→1） | ≈6 300 | 简单 | 丢时间结构，参数翻倍，易过拟合 |
| **1-D CNN ×3 + GAP** | **3 061** | **保留时间模式、参数最少、可 int8 上 MCU** | 只有 8 个时间步，感受野刚好够 |
| LSTM | ≈5 000+ | 长程依赖 | 有状态、难量化、MCU 上麻烦 |
| Transformer | ≫10 000 | 表达力强 | 小样本必然过拟合，算力不合适 |

三个理由：

1. **时间局部性**：专注表现为"连续几秒的模式"，卷积核在时间轴滑动正好捕捉它；
2. **参数预算**：brief 要求 ≈3k 参数、TFLite Micro 可跑。3 层卷积 + GAP 做到 3 061，
   int8 后 3.1 KB、单次 24.0 kMAC——MCU 上几十微秒；
3. **可解释**：第 3 层 24 个通道各自对应一种"8 秒内的波形模板"，GAP 之后是一个线性层，
   可以打印每个通道的权重，看出模型更依赖哪种模式（见第 4 节）。

**输入为什么是 8×12 而不是原始 512 Hz 波形？**
8 秒的原始波形是 4 096 个点，直接卷积需要的参数与算力远超预算；而且设备已经把
频域信息算成了 8 段功率。12 维特征 = 设备 eSense 的 attention + 8 段对数功率
+ attention 差分 + 2 个伪迹指标。原方案里的 `signal` 与 `meditation` 被剔除了：
前者是电极接触质量（与"是否专注"无关，还会因训练集方差为 0 而在验证集上放大成
1e5 量级的 z 值），后者跨会话漂移（单特征 AUC 只有 0.42）。这条不是拍脑袋：
真实数据上逐特征 AUC 实测 attention 0.879、log-lowGamma 0.895，而 `raw_std` 0.318
（方向还反了）——把"手眼运动"当专注的捷径在 v3 协议里已经被堵住。

**训练与验证**：二元交叉熵 + Adam + **按验证 AUC 早停**（patience 60）+ 时间平移/增益/噪声增强；
**按会话文件分组切分** 80/20（同一段数据不会同时出现在训练和验证），
**标准化参数只用训练会话计算**（验证会话完全不参与）。反向传播手写，并用中心差分数值梯度
校验了全部 3 061 个参数（余弦相似度 0.999996）——保证"能学"是模型本身的功劳，而不是框架的黑盒。

## 4. 挑战（以及怎么应对）

1. **样本太少**：本机目前只有 2 段真实会话（474 个窗口，约 66 个独立块），
   留一会话之后只有 1 段训练，指标不确定度约 ±6–7 个百分点。
   → 增强、GAP 降参、早停、分组切分；报告里写明"需要 3 位以上被试才有可信的均值"。
2. **个体差异**：两种标准化方式实测差别不大——用训练会话的 μ/σ 固定阈值 0.5 是
   **0.890**，用本人 50 秒静息重估 μ/σ 并把阈值定在静息打分的 90 分位是 **0.880**。
   所以部署时"本人静息校准"是**可选项**（换了人、阈值明显不合适时再做），
   而不是必须流程；这也说明模型学到的东西跨会话可迁移，不是记住某个人的漂移。
3. **标签噪声**：被试"假装专注"、心算卡住、走神。→ 两种状态都闭眼、都不动手，
   心算段默算"1000 连续减 7"，段末报数写进 `*_tasks.csv` 留行为证据；每段前 10 s 丢弃，多段平均。
4. **伪迹**：眨眼、咬牙、吞咽、头动。→ 三个条件一起判：TGAM 的"没戴好"码
   （29/54/55/56/80/81/82/107/200）、`signal > 100`、以及"稳健 4σ / 全局 99.5 分位 / 4×中位数"
   三者取最松的那个作为 `raw_std` 上限（本机实测 280.1，只剔掉 6 秒）。
   注意这个上限不能取紧：`raw_std` 在本数据里与"静息"正相关（AUC 0.318），
   卡得严会把要学的静息秒当成伪迹删掉——旧代码的 2500 硬下限则是另一个极端，等于没清洗。
5. **设备黑盒**：attention 由厂商算法给出，不可解释。→ 只当特征不当标签，
   报告中单独讨论其影响。
6. **1 Hz 太粗**：8 秒窗口只有 8 个时间步。→ 加 attention 差分；未来可把
   512 Hz 原始波形降采样成多通道输入。
