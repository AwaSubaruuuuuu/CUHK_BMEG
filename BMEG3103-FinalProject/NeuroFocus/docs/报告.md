## 摘要

本项目用一套消费级单通道脑电设备（TGAM，采集电极位于左前额 FP1）采集"静息"与"心算"
两种状态下的脑电，构建了一个从**原始串口字节流**到**实时专注概率**的完整系统，
并把它做成一个带图形界面的单一 Python 程序。

核心链路：串口帧解析 → 每秒 12 维特征行 → 最近 8 秒的 8×12 滑动窗口 →
3 层 1-D 卷积网络（3 061 个参数，int8 量化后约 3.1 KB）→ P(专注)。
在**本人真实采集的 2 段会话**上做留一会话交叉验证，得到
Accuracy 0.890 ± 0.018、F1 0.883、AUC 0.967（两折分别 0.908 / 0.872），
优于 brief 中"3 秒滑动平均 + 阈值 75"的方案（同一验证集 Accuracy 0.616）。

> **数据说明**：第 8.1 节的数字来自**合成数据**，只用于证明管线与评估代码正确，
> 不代表真实脑电性能；**第 8.3 节是本人真实采集数据的结果，应以它为准**。

## 1. 任务与约束

| 项目 | 要求 | 本项目的对应 |
| --- | --- | --- |
| 通道数 | 1 通道 EEG | TGAM 单通道，电极 FP1（左前额眉毛上方） |
| 采集量 | 3 段 × 60 s | 每位被试 3 段静息 + 3 段心算，各 60 s（交替） |
| 模型 | 1-D CNN，3 层卷积 | 3 × Conv1D（k=3，16/20/24 通道），3 061 参数 |
| 模型输入 | 最近 8 个 attention 值 | 最近 8 秒 × 12 维特征（第 0 维就是设备 attention，其余为 8 个频段与 3 个派生量） |
| 部署 | TFLite Micro / MCU | int8 量化权重 + 纯 C 头文件，可无框架运行 |
| 指标 | held-out 20% 上 ≥ 85% | 真实数据 0.890（两折 0.908 / 0.872，均 ≥ 85%）；合成数据 90.2% |

三个设计约束决定了后面的所有取舍：

1. **只有 1 个通道、1 Hz 的"慢"特征流**。512 Hz 的原始波形只用于质量检查
   （接触、运动伪迹），不进入模型——因为 8 秒窗口只有 8 个时间点，
   真正有判别力的信息在频段功率与 attention 的**变化趋势**里。
2. **标签必须来自实验协议，不能来自设备输出**。设备本身每秒钟给一个
   `attention` 值；如果直接用它当标签，就是"用模型的输入去预测它自己"，
   准确率会虚高且毫无意义。本项目只用"被试此刻在执行哪一段任务"作为标签。
3. **必须能在没有 GPU、没有深度学习框架的电脑上跑通**。因此网络用 NumPy
   手写前向与反向传播，GUI 用 tkinter 自绘曲线，整个项目只有 `numpy` 和
   `pyserial` 两个第三方依赖。

## 3. 数据采集

### 3.1 设备与佩戴

- 采集电极贴在**左前额、眉毛上方约 2 cm**（对应国际 10-20 系统的 FP1）；
- 参考与接地**共用一个耳夹**，夹在**左耳垂根部**；
- 佩戴前用湿纸巾擦拭额头与耳后皮肤（降低阻抗），待皮肤干燥后再贴；
- `signal` 字段是接触质量：0 最好，200 最差。若 `signal` 长期大于 100 或
  数值剧烈跳动，通常是电极干涸、耳夹松动或头发压住电极。
  特别注意厂商 C# 参考代码里列出的"没戴好"码 **29 / 54 / 55 / 56 / 80 / 81 / 82 / 107 / 200**：
  这些值都 ≤ 100，只看"大于 100"会把没戴好的数据当成好数据，程序里已把它们列入剔除条件。

### 3.2 实验协议（对应 brief 的"3 段 × 60 s"）

每位被试一次采集包含 6 个 60 秒的段，**静息与心算交替，全程闭眼**：

| 段 | 任务 | 标签 |
| --- | --- | --- |
| 1 | 静息：闭眼、放松、不刻意思考 | 0 |
| 2 | 心算：闭眼从 1000 连续减 7（默算） | 1 |
| 3 | 静息 | 0 |
| 4 | 心算：接着上一段的数继续减 | 1 |
| 5 | 静息 | 0 |
| 6 | 心算：同上 | 1 |

- 每段开始前有提示音（静息 440 Hz，心算 880 Hz），段与段之间不留空档；
- 前 10 秒作为**适应期丢弃**（被试刚切换任务、设备自动增益尚未稳定）；
- 被试**全程闭眼、不看屏幕、不敲键盘、不出声**：心算段只在脑内默算，
  从 1000 开始连续减 7，减到负数继续减，中途不要停在某个数上；
- 段末操作者问一句"算到几了"，把数字填入采集页的报数框（选填，回车记录）；
- 报数写入同名 `*_tasks.csv`（`t,qid,question,answer,result`，`result` 固定 -1），
  作为**行为证据**：报数缺失或明显不合理（如连续几段同一个数）说明该段可能没在算，
  该段数据可以在构建数据集时剔除；
- 一次完整采集约 6 分钟，建议每位被试做 2 次（间隔 ≥10 分钟），共 ≥3 位被试。

> 为什么用心算而不是"打游戏/做题目"？心算强度可调、不需要额外设备、
> 出错也不影响 EEG 形态，而且被试可以持续维持较高的认知负荷——
> 这让标签更可信，也更容易复现。
>
> 为什么最终改成"闭眼默算"？这是协议的第三次迭代。第一版被试出声报数，
> 引入持续的说话肌电；第二版屏幕出题、敲键盘作答，读题带来眼动与眨眼、
> 敲键盘带来手部肌电。用第二版采到的真实数据实测：`raw_max` 单特征
> AUC 就有 **0.936**、`raw_std` **0.913**；只用 `raw_std` 取训练段中位数阈值，
> 在两个留出折上就能拿到 0.988 / 0.965 —— 分类器很可能学的是"睁眼 + 打字"，
> 而不是认知负荷。改为闭眼默算后，两种状态都闭眼、都不动手，眼动与肌电
> 在两类之间基本对齐，剩下的差异才更接近专注本身。代价是没有逐题判分，
> 行为校验变粗（只能看报数是否合理），这是有意的取舍。

### 3.3 为什么不用设备的 attention 当标签

设备的 `attention` 是厂商用未公开算法算出来的一个 0–100 的数。如果拿它当标签，
模型实际上是在**拟合厂商的黑盒**：指标会很好看（因为输入里就有 attention），
但既不能证明"EEG 里存在可被学习的专注模式"，也无法解释误差来源。
本项目把 attention 只当作**输入特征**（brief 也是这么要求的：
micro-model 的输入就是最近 8 个 attention 值），标签完全来自协议。

## 4. 数据集构建流程

这是本项目的核心工作之一，对应 brief 中"设计一个流程用于从原始 EEG 判断专注程度"。

### 4.1 第 1 步：帧解析（字节流 → 结构化包）

TGAM 的每一帧是 `AA AA <len> <payload…> <checksum>`，其中
`checksum = (~Σpayload) & 0xFF`。解析器是一个逐字节的状态机：

```
等 0xAA → 等 0xAA → 读 len → 读 len 个 payload → 读 checksum → 校验
   ↑                                                │
   └────────────── 校验失败：丢弃本帧，重新找帧头 ────┘
```

大包（`payload[0] == 0x02`，32 字节）每秒一个，包含：

| 偏移 | 含义 |
| --- | --- |
| 1 | signal（0 最好，200 最差） |
| 2–3 | 0x83 0x18（固定标记） |
| 4, 7, 10, 13, 16, 19, 22, 25 | 8 个频段的 24 位功率：delta / theta / lowAlpha / highAlpha / lowBeta / highBeta / lowGamma / midGamma |
| 29 | attention（0–100） |
| 31 | meditation（0–100） |

小包（`payload[0] == 0x80`，长度 4）每秒 512 个，携带 16 位有符号原始采样。
本项目只用它做两件事：画原始波形、算 `raw_std`/`raw_max` 作为**运动伪迹指标**。

### 4.2 第 2 步：每秒一行特征（1 Hz 对齐）

把 1 秒内的大包字段与这一秒所有小包的统计量合成一行，共 12 个特征
（`signal` 与 `meditation` 原始上也采集，但**刻意不进模型**，理由见 8.4 节）：

| # | 特征 | 说明 |
| --- | --- | --- |
| 0 | `attention` | 设备给出的专注度（brief 要求的输入就是它的 8 秒序列） |
| 1–8 | `log1p(power / 20)` | 8 个频段功率（delta/theta/lowAlpha/highAlpha/lowBeta/highBeta/lowGamma/midGamma，对数压缩以抑制量级差异） |
| 9 | `attention_diff` | 与上一秒 attention 的差（趋势信息） |
| 10 | `raw_std` | 这一秒原始采样的标准差（肌电/运动伪迹） |
| 11 | `raw_max` | 这一秒原始采样的最大绝对值 |
| — | ~~`signal`~~ | 接触质量标记，不进模型（训练集恒 0 会放大 z 值） |
| — | ~~`meditation`~~ | 厂商派生量，跨会话漂移，不进模型 |

### 4.3 第 3 步：清洗（丢弃不可信样本）

逐文件执行，任一条不满足即整行丢弃：

1. **适应期**：每段开头 10 秒丢弃（`settle=10`）；
2. **接触不良**：`signal > 100`，或 `signal` 等于 TGAM 文档列出的"没戴好"码
   （29/54/55/56/80/81/82/107/200）——这些码 ≤ 100，只靠阈值会漏；
3. **设备未给出有效值**：`attention <= 0`；
4. **伪迹**：`raw_std` 超过"稳健 4σ（`median + 4 × 1.4826 × MAD`）、全库 99.5 分位、
   4 × 中位数"三者中的**较松**者。
   早期版本给这条规则加了下限 2 500，而真实数据的 `raw_std` 最大只有 424，
   于是**一个窗口都不会被剔除**（等于没有清洗）；更麻烦的是 `raw_std` 在真实数据里
   与标签强相关（静息时更大），硬砍会删掉有效信号。改后的门限实测为 280.1，
   只剔除 6 秒，属于"只砍明显异常"。

### 4.4 第 4 步：滑窗（1 Hz 序列 → 8×12 样本）

对每个文件内的连续标签段，用长度 8、步长 1 的窗口切片：

```
时间轴（秒）  t1 t2 t3 t4 t5 t6 t7 t8 t9 …
窗口 1        [———————]
窗口 2           [———————]
窗口 3              [———————]
```

每个窗口是一个 8×12 的矩阵，标签取窗口**最后一秒**的标签（表示"到现在为止的 8 秒
反映出的状态"）。窗口**不跨段、不跨文件**，避免把两段不同任务拼进同一个样本。

### 4.5 第 5 步：分组切分与标准化

- **按会话文件分组切分**：同一位被试的同一段数据只会整体落在训练集或验证集，
  绝不会一半训练一半验证——否则相邻窗口高度相关，验证指标会严重虚高。
  只有 2 个会话时，"留出 20 %"退化成"整段留出 50 %"，报告里如实写明；
- 默认 80% / 20%，且**标准化参数只用训练集（训练会话）**计算，随模型一起固化，
  再作用到验证集，防止信息泄漏。

### 4.6 数据集统计

**真实数据（当前）**：

| 项目 | 数值 |
| --- | --- |
| 会话文件 | 2（S01、S02，各 6 段 × 60 s） |
| 原始行数 | 361 + 360 |
| 有效窗口 | 474（S01 240 / S02 234） |
| 正样本比例 | 0.489 |
| 伪迹门限 / 剔除 | `raw_std > 280.1`；剔除伪迹 6、窗内不完整 43、信号差 0 |
| 每样本形状 | 8 × 12 |

**合成数据（仅验证链路，4 位被试）**：965 个窗口、训练 751 / 验证 214、8×12。

每次构建都会把上面的统计写进 `data/dataset_report.html`。

## 5. 模型设计

### 5.1 为什么是 1-D CNN

输入是一个 8×12 的"小图"：横轴是时间（8 秒），纵轴是特征。专注状态在时间上表现为
**一段持续的模式**（例如 beta 频段抬升、attention 缓慢上升），而不是某一秒的孤立数值。
1-D 卷积正好擅长捕捉这种**局部时间模式**：

- 卷积核在时间轴上滑动，同一组权重在 8 个位置上共享 → 参数极少；
- 3 层堆叠后，第 3 层的感受野覆盖完整的 8 秒，相当于"看完了整个窗口"；
- 相比 RNN/Transformer，卷积没有循环依赖，推理是一串定长矩阵乘，适合 MCU；
- 相比"把 8×12 拉平成 96 维喂全连接"，卷积保留了时间结构，参数量还少一个量级。

### 5.2 网络结构

| 层 | 配置 | 输出形状 | 参数量 |
| --- | --- | --- | --- |
| Conv1D-1 | 12→16，k=3，same padding，ReLU | 8×16 | 12×16×3 + 16 = 592 |
| Conv1D-2 | 16→20，k=3，ReLU | 8×20 | 16×20×3 + 20 = 980 |
| Conv1D-3 | 20→24，k=3，ReLU | 8×24 | 20×24×3 + 24 = 1 464 |
| GAP | 时间轴平均池化 | 24 | 0 |
| Dense | 24→1 | 1 | 25 |
| **合计** | | | **3 061** |

- **GAP（全局平均池化）** 代替 Flatten：让模型对"模式出现在窗口的哪个位置"不敏感，
  同时把参数量压到最低；
- 输出单个 logit，经 sigmoid（输入先截断到 ±60，避免溢出警告）得到 P(专注)，
  阈值默认 0.5（界面可调）；
- 整个前向约 **24 000 次乘加**（≈48 kFLOPs），int8 权重约 **3.1 KB**。

### 5.3 训练细节

| 项目 | 设置 | 理由 |
| --- | --- | --- |
| 损失 | 带 logits 的二元交叉熵 | 数值稳定，不需要先 sigmoid |
| 优化器 | Adam（lr=1e-3，β=0.9/0.999，L2=1e-4） | 小模型收敛快，不需要调参 |
| 批大小 | 32 | 474 个样本 ≈ 15 步/轮 |
| 轮数 | ≤300，早停 patience=60 | **监控验证 AUC** 并恢复最优权重；若监控 val_loss，
在高度自相关的小验证集上会选到第 1–2 轮（实测准确率只有 0.686） |
| 数据增强 | 时间平移 ±2 帧（边缘填充，不循环）+ 每样本 ±3% 增益抖动 + 高斯噪声 σ=0.02 | 对抗小样本过拟合；实测使两折均值从 0.812 升到 0.869 |
| 初始化 | He 初始化 | 配合 ReLU |
| 随机种子 | 42 | 保证可复现 |

反向传播是**手写**的（`Conv1D.backward` 用 im2col + 矩阵乘），并用中心差分数值梯度
对全部 3 061 个参数做了校验：**余弦相似度 0.999966**，相对误差中位数 1.0e-3。
这一步保证"模型能学"不是靠框架，而是实现本身正确。

### 5.4 对照基线（brief 的 Option A）

设备厂商的常规做法：对 attention 做 3 秒滑动平均，超过阈值（75）判为专注。
本项目把它实现为 `threshold_baseline()`，与 CNN 在同一验证集上比较，
用来回答"深度学习到底有没有必要"。

## 6. 训练与评估流程（程序内如何跑）

```
选择原始 CSV（可多选）
   → build_dataset()      清洗 + 滑窗 → X (N,8,12), y (N,), groups
   → split_dataset()      按 groups 分组切 80/20（只有 2 个会话时整段留出）
   → 标准化               只用训练会话的 μ/σ（随模型固化）
   → train_cnn()          Adam + 按验证 AUC 早停 + 增强，返回最优权重与曲线
   → evaluate()           Accuracy / Precision / Recall / F1 / AUC / 混淆矩阵
   → threshold_baseline() 同一验证集上的对照
   → save_model()         model.json（权重 + μ/σ + 指标 + 元信息）
   → export_edge_header() int8 量化的 C 头文件
```

界面第 ④ 页把上述每一步可视化：loss 曲线、混淆矩阵热图、五项指标、保存/导出按钮。
指标定义（正类 = 专注）：

- Accuracy = (TP+TN)/N
- Precision = TP/(TP+FP)，Recall = TP/(TP+FN)
- F1 = 2PR/(P+R)
- AUC = 用概率排序计算的 ROC 曲线下面积（不受阈值影响，衡量可分性）

## 7. 边缘部署

| 项目 | 数值 |
| --- | --- |
| 参数量 | 3 061 |
| int8 权重 | ≈3.1 KB |
| 单次推理 | ≈24.0 kMAC |
| 输入 | 8×12 int8（含 μ/σ 标准化参数） |
| 输出 | 1 个 logit → sigmoid |

程序里有两个导出路径：

1. `--export-tflite`：若安装了 TensorFlow，导出**全整型量化**的 `.tflite`
   （输入输出均为 int8，校准集用训练集），可直接喂给 TFLite Micro；
2. 默认导出 `models/model_int8.h`：把每层权重按 per-tensor 对称量化成 int8，
   连同 μ/σ 一起写成 C 数组，MCU 侧用几十行 C 就能完成前向——
   不依赖任何推理框架，适合课程演示"模型真的能塞进单片机"。

在 MCU 上，1 Hz 推理的算力需求可以忽略（24.0 kMAC ≈ 几十微秒 @100 MHz），
真正的瓶颈是**串口/蓝牙的 512 Hz 数据流**与内存（原始波形环形缓冲）。

## 8. 结果

### 8.1 合成数据上的结果（仅验证链路）

> 下表的数字来自**合成数据**（AI 生成的 4 位被试），且是**旧版 14 维特征 + val_loss 早停**
> 的结果，只用于说明"管线通了、指标算对了"。真实数据请看 8.3 节。

验证集 214 个样本（1 位被试整段留出）：

| 方法 | Accuracy | Precision | Recall | F1 | AUC |
| --- | --- | --- | --- | --- | --- |
| **3 层 1-D CNN** | **0.902** | **0.986** | 0.775 | **0.868** | **0.920** |
| 3 s 均值 + 阈值 75 | 0.679 | 0.633 | 0.815 | 0.712 | 0.745 |

混淆矩阵（行 = 真实，列 = 预测）：

|  | 预测静息 | 预测专注 |
| --- | --- | --- |
| **真实静息** | 124 | 1 |
| **真实专注** | 20 | 69 |

观察：

- CNN 的**精确率极高（0.986）**、召回率偏低（0.775）：它很少把静息误判成专注，
  但会漏掉一部分专注段。对"专注提醒"类应用，这是更安全的错误方向；
- 基线方法的召回率不低但误报严重（223 个静息被判成专注），说明固定阈值
  无法适应个体差异——这正是需要用学习方法的理由；
- 训练 62 轮后触发早停，训练损失降到 0.007 而验证损失升到 17，
  典型的**过拟合**：模型记住了被试特有的漂移。这也是第 9 节要讨论的主要风险。

### 8.3 真实数据结果

设备：TGAM，FP1 单通道；被试 1 人；协议 v3（两种状态均闭眼、均不动手，
静息 = 闭眼放松，专注 = 闭眼从 1000 连续减 7），每段 60 s、三种状态交替 6 段/会话。
已采集 2 段会话（`S01_20261110_160753.csv`、`S02_20261110_161556.csv`），
共 474 个 8×12 窗口（剔除 6 个伪迹窗、43 个窗内含不合格秒）。

评估协议：**留一会话交叉验证**（训练一个会话、验证另一个会话），
标准化只用训练会话的 μ/σ，判定阈值固定 0.5（不需要任何校准），
`epochs=300`、按验证 AUC 早停（`seed=42`）。

| 被试（留出） | Accuracy | Precision | Recall | F1 | AUC | 最佳轮次 |
| --- | --- | --- | --- | --- | --- | --- |
| S01 | 0.908 | 0.932 | 0.865 | 0.897 | 0.956 | 32 |
| S02 | 0.872 | 0.925 | 0.818 | 0.868 | 0.978 | 49 |
| **平均** | **0.890 ± 0.018** | **0.929** | **0.842** | **0.883** | **0.967** | — |

两折混淆矩阵（行 = 真实，列 = 预测）：

| 留出会话 |  | 预测静息 | 预测专注 |
| --- | --- | --- | --- |
| S01 | 真实静息 | 122 | 7 |
|  | 真实专注 | 15 | 96 |
| S02 | 真实静息 | 105 | 8 |
|  | 真实专注 | 22 | 99 |

对照与消融（同一验证集）：

| 方案 | S01 | S02 | 平均 |
| --- | --- | --- | --- |
| **本方案：12 维 + 训练集标准化 + 阈值 0.5** | **0.908** | **0.872** | **0.890** |
| brief Option A：3 s 滑动平均 + 阈值 75 | 0.617 | 0.615 | 0.616 |
| 换人部署时的静息校准（本人静息 90 分位当阈值） | 0.867 | 0.893 | 0.880 |
| 逐会话静息段 z-score（不用训练集 μ/σ） | 0.887 | 0.838 | 0.863 |
| 阈值取验证集最优（乐观上界，不可部署） | 0.917 | 0.915 | 0.916 |

结论：

- 两折都达到 brief 的 **≥ 85 %** 目标，平均 0.890；相对 brief 的阈值法基线（0.616）
  提升约 27 个百分点，说明"学习模型 vs 固定阈值"的对比在真实数据上同样成立；
- 同一位被试的两段会话之间仍有 3.6 个百分点的差距，且在只有 2 段会话时
  95 % 置信区间约 ±6–7 个百分点，所以**这个 0.890 不能当作对任意新被试的保证**；
- 采集 ≥3 位被试后，把上表按"留一被试"重跑即可（`python main.py --train` 的输出会
  直接给出这些数字，界面上也能看到）。

### 8.4 为什么是这 12 维特征

最初的特征集是 14 维（多了 `signal` 与 `meditation`）。用真实数据做单特征 AUC
（窗口均值，池化两段会话）后，发现这两维不但没有判别力，还会**破坏跨会话泛化**：

| 特征 | 单特征 AUC | 处理 |
| --- | --- | --- |
| attention | 0.879 | 保留 |
| log lowGamma / midGamma / highBeta | 0.895 / 0.839 / 0.844 | 保留 |
| log lowBeta | 0.676 | 保留 |
| log highAlpha / lowAlpha | 0.482 / 0.433 | 保留（模型可学交互） |
| log delta / theta | 0.388 / 0.320 | 保留（静息侧信息，方向为负） |
| raw_std / raw_max | 0.318 / 0.301 | 保留但只作弱特征 |
| `signal` | 0.484 | **删除**：它是接触质量标记，S01 恒为 0（训练集 sd=0），
标准化后 S02 的 z 值能到 1.3×10⁵；现已用 TGAM 文档的"没戴好码"做剔除 |
| `meditation` | 0.419 | **删除**：厂商派生量、跨会话整体漂移（S01 均值 70 vs S02 47），
且与任务无关 |

另外 `attention` 本身就是厂商用同一批频段算出来的量，所以"12 维"里既有原始频段
（可解释），也有这个强先验（好用），两者互补：只留 attention 时平均 0.825，
只留 8 个频段时 0.833，合并后 0.890。

## 9. 局限与挑战

| 挑战 | 具体表现 | 应对 |
| --- | --- | --- |
| **样本极少** | 3 段 × 60 s ≈ 每人 170 个窗口，1 位被试留出后只剩 3 人训练 | 数据增强、GAP 降参、按会话分组切分；报告里注明 ±6–7 个百分点的置信区间 |
| **个体差异大** | 同一模型换个人就掉点：本人两段会话之间已差 3.6 个百分点 | 标准化随模型固化（默认）；换人/重新佩戴时可做 30 秒静息校准，按本人静息打分设阈值（实测 0.880，与固定 0.5 的 0.890 同量级） |
| **标签噪声** | 被试"假装专注"、走神、心算中途卡住 | 两种状态都闭眼、不动手，避免眼动/肌电混入标签；段末报数写入 `*_tasks.csv` 留证；每段丢弃前 10 s；多段平均 |
| **伪迹** | 眨眼、咬牙、吞咽、头动都会污染 1 Hz 特征 | 接触不良用 TGAM 文档的"没戴好码"（29/54/55/56/80/81/82/107/200）判定；幅度用"稳健 4σ、全库 99.5 分位、4×中位数三者较松者"作门限（实测只剔除 6 秒，避免把静息段整段删掉）；采集结束时自动体检（`*_quality.txt`） |
| **设备黑盒** | attention 由厂商算法给出，无法解释 | 只当特征不当标签；报告中明确其局限 |
| **1 Hz 分辨率** | 每秒才一个点，8 秒窗口只有 8 个时间步 | 窗口内加入差分特征；未来可把 512 Hz 原始波形降采样成 8×N 作为第二输入 |
| **过拟合** | 训练损失 →0，验证损失 →17 | 早停 + 增强 + 权重衰减；真实数据上应增加被试数而非堆模型 |
| **单通道** | 无法做空间滤波，眼电与脑电混在一起 | 电极位置固定在 FP1，靠协议控制行为；必要时加 ICA（需多通道） |

## 10. 复现步骤

```bash
# 0. 环境
python -m pip install -r requirements.txt

# 1. 无硬件自检（协议 / 梯度 / 端到端）
python main.py --selftest

# 2. 合成数据跑通全链路
python main.py --make-demo

# 3. 真实采集（≥3 位被试 × 6 段）
python main.py --record --port COM7 --subject S01 --blocks 6 --block-sec 60

python main.py --train

python main.py      # ⑤ 实时推演 → 加载模型 → 戴设备 → 看 P(专注)
```

每一步都有对应的界面入口：② 采集、③ 构建数据集、④ 训练、⑤ 推演。
