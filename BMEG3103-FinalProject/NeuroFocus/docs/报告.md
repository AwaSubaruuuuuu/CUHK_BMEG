## 摘要

本项目用一套消费级单通道脑电设备（TGAM，采集电极位于左前额 FP1）采集"静息"与"心算"
两种状态下的脑电，构建了一个从**原始串口字节流**到**实时专注概率**的完整系统，
并把它做成一个带图形界面的单一 Python 程序。

核心链路：串口帧解析 → 每秒 14 维特征行 → 最近 8 秒的 8×14 滑动窗口 →
3 层 1-D 卷积网络（3 157 个参数，int8 量化后约 3.2 KB）→ P(专注)。
在 4 位被试（合成数据，仅用于验证链路）上，留一被试交叉验证得到
Accuracy 0.902、F1 0.868、AUC 0.920，明显优于"3 秒滑动平均 + 阈值 75"的
设备内置方案（Accuracy 0.679）。

> **数据说明**：本报告中的全部数值均在**合成数据**上得到，用于证明管线与评估代码正确，
> 不代表真实脑电的性能。真实指标需用 `docs/采集协议.md` 采集的数据重新训练后填写
> （第 8.3 节给出了需要替换的表格位置）。

## 1. 任务与约束

| 项目 | 要求 | 本项目的对应 |
| --- | --- | --- |
| 通道数 | 1 通道 EEG | TGAM 单通道，电极 FP1（左前额眉毛上方） |
| 采集量 | 3 段 × 60 s | 每位被试 3 段静息 + 3 段心算，各 60 s（交替） |
| 模型 | 1-D CNN，3 层卷积 | 3 × Conv1D（k=3，16/20/24 通道），3 157 参数 |
| 模型输入 | 最近 8 个 attention 值 | 最近 8 秒 × 14 维特征（其中第 0 维就是设备 attention） |
| 部署 | TFLite Micro / MCU | int8 量化权重 + 纯 C 头文件，可无框架运行 |
| 指标 | held-out 20% 上 ≥ 85% | 合成数据 90.2%；真实数据待补 |

三个设计约束决定了后面的所有取舍：

1. **只有 1 个通道、1 Hz 的"慢"特征流**。512 Hz 的原始波形只用于质量检查
   （接触、运动伪迹），不进入模型——因为 8 秒窗口只有 8 个时间点，
   真正有判别力的信息在频段功率与 attention 的**变化趋势**里。
2. **标签必须来自实验协议，不能来自设备输出**。设备本身每秒钟给一个
   `attention` 值；如果直接用它当标签，就是"用模型的输入去预测它自己"，
   准确率会虚高且毫无意义。本项目只用"被试此刻在执行哪一段任务"作为标签。
3. **必须能在没有 GPU、没有深度学习框架的电脑上跑通**。因此网络用 NumPy
   手写前向与反向传播，GUI 用 tkinter 自绘曲线，整个项目只有 `numpy` 和
   `pyserial` 两个第三方依赖。

## 3. 数据采集

### 3.1 设备与佩戴

- 采集电极贴在**左前额、眉毛上方约 2 cm**（对应国际 10-20 系统的 FP1）；
- 参考与接地**共用一个耳夹**，夹在**左耳垂根部**；
- 佩戴前用湿纸巾擦拭额头与耳后皮肤（降低阻抗），待皮肤干燥后再贴；
- `signal` 字段是接触质量：0 最好，200 最差。若 `signal` 长期大于 100 或
  数值剧烈跳动，通常是电极干涸、耳夹松动或头发压住电极。

### 3.2 实验协议（brief 要求 ≥3 段 × 60 s，本项目每次会话采 8 段）

每次会话包含 8 个 60 秒的段，**静息与心算交替，全程闭眼**：

| 段 | 任务 | 标签 |
| --- | --- | --- |
| 1 | 静息：闭眼、放松、不刻意思考 | 0 |
| 2 | 心算：闭眼从 1000 连续减 7（默算） | 1 |
| 3 | 静息 | 0 |
| 4 | 心算：接着上一段的数继续减 | 1 |
| 5 | 静息 | 0 |
| 6 | 心算：同上 | 1 |
| 7 | 静息 | 0 |
| 8 | 心算：同上 | 1 |

- 每段开始前有提示音（静息 440 Hz，心算 880 Hz），段与段之间不留空档；
- 前 10 秒作为**适应期丢弃**（被试刚切换任务、设备自动增益尚未稳定）；
- 被试**全程闭眼、不看屏幕、不敲键盘、不出声**：心算段只在脑内默算，
  从 1000 开始连续减 7，减到负数继续减，中途不要停在某个数上；
- 段末操作者问一句"算到几了"，把数字填入采集页的报数框（选填，回车记录）；
- 报数写入同名 `*_tasks.csv`（`t,qid,question,answer,result`，`result` 固定 -1），
  作为**行为证据**：报数缺失或明显不合理（如连续几段同一个数）说明该段可能没在算，
  该段数据可以在构建数据集时剔除；
- 一次会话 8 分钟；**主数据集 = 1 位被试 × 8 次会话**（每次重新贴电极、间隔 ≥10 分钟），
  共 64 分钟、约 2 752 个窗口。为什么不用"1 位被试 6 段"：单个会话只有 1 个分组，
  无法做留一会话验证，任何指标都会因窗口重叠而虚高（4.5 节与 8.3 节的实测差距）。
  8 次会话才能做 8 折交叉验证，也才能回答"换一天戴还准不准"。

> 为什么用心算而不是"打游戏/做题目"？心算强度可调、不需要额外设备、
> 出错也不影响 EEG 形态，而且被试可以持续维持较高的认知负荷——
> 这让标签更可信，也更容易复现。
>
> 为什么最终改成"闭眼默算"？这是协议的第三次迭代。第一版被试出声报数，
> 引入持续的说话肌电；第二版屏幕出题、敲键盘作答，读题带来眼动与眨眼、
> 敲键盘带来手部肌电。用第二版采到的真实数据实测：`raw_max` 单特征
> AUC 就有 **0.936**、`raw_std` **0.913**；只用 `raw_std` 取训练段中位数阈值，
> 在两个留出折上就能拿到 0.988 / 0.965 —— 分类器很可能学的是"睁眼 + 打字"，
> 而不是认知负荷。改为闭眼默算后，两种状态都闭眼、都不动手，眼动与肌电
> 在两类之间基本对齐，剩下的差异才更接近专注本身。代价是没有逐题判分，
> 行为校验变粗（只能看报数是否合理），这是有意的取舍。

### 3.3 为什么不用设备的 attention 当标签

设备的 `attention` 是厂商用未公开算法算出来的一个 0–100 的数。如果拿它当标签，
模型实际上是在**拟合厂商的黑盒**：指标会很好看（因为输入里就有 attention），
但既不能证明"EEG 里存在可被学习的专注模式"，也无法解释误差来源。
本项目把 attention 只当作**输入特征**（brief 也是这么要求的：
micro-model 的输入就是最近 8 个 attention 值），标签完全来自协议。

## 4. 数据集构建流程

这是本项目的核心工作之一，对应 brief 中"设计一个流程用于从原始 EEG 判断专注程度"。

### 4.1 第 1 步：帧解析（字节流 → 结构化包）

TGAM 的每一帧是 `AA AA <len> <payload…> <checksum>`，其中
`checksum = (~Σpayload) & 0xFF`。解析器是一个逐字节的状态机：

```
等 0xAA → 等 0xAA → 读 len → 读 len 个 payload → 读 checksum → 校验
   ↑                                                │
   └────────────── 校验失败：丢弃本帧，重新找帧头 ────┘
```

大包（`payload[0] == 0x02`，32 字节）每秒一个，包含：

| 偏移 | 含义 |
| --- | --- |
| 1 | signal（0 最好，200 最差） |
| 2–3 | 0x83 0x18（固定标记） |
| 4, 7, 10, 13, 16, 19, 22, 25 | 8 个频段的 24 位功率：delta / theta / lowAlpha / highAlpha / lowBeta / highBeta / lowGamma / midGamma |
| 29 | attention（0–100） |
| 31 | meditation（0–100） |

小包（`payload[0] == 0x80`，长度 4）每秒 512 个，携带 16 位有符号原始采样。
本项目只用它做两件事：画原始波形、算 `raw_std`/`raw_max` 作为**运动伪迹指标**。

### 4.2 第 2 步：每秒一行特征（1 Hz 对齐）

把 1 秒内的大包字段与这一秒所有小包的统计量合成一行，共 14 个特征：

| # | 特征 | 说明 |
| --- | --- | --- |
| 0 | `attention` | 设备给出的专注度 |
| 1 | `meditation` | 设备给出的放松度 |
| 2 | `signal` | 接触质量 |
| 3–10 | `log1p(power / 20)` | 8 个频段功率（对数压缩，抑制量级差异） |
| 11 | `attention_diff` | 与上一秒 attention 的差（趋势信息） |
| 12 | `raw_std` | 这一秒原始采样的标准差（肌电/运动伪迹） |
| 13 | `raw_max` | 这一秒原始采样的最大绝对值 |

### 4.3 第 3 步：清洗（丢弃不可信样本）

逐文件执行，任一条不满足即整行丢弃：

1. **适应期**：每段开头 10 秒丢弃（`settle=10`）；
2. **接触不良**：`signal > 100`；
3. **设备未给出有效值**：`attention <= 0`；
4. **伪迹**：`raw_std` 超过 `median + 4 × 1.4826 × MAD`（稳健的 4σ 规则），
   且下限为 2 500——即"明显高于本人基线的抖动"才丢，避免把正常个体差异当伪迹。

### 4.4 第 4 步：滑窗（1 Hz 序列 → 8×14 样本）

对每个文件内的连续标签段，用长度 8、步长 1 的窗口切片：

```
时间轴（秒）  t1 t2 t3 t4 t5 t6 t7 t8 t9 …
窗口 1        [———————]
窗口 2           [———————]
窗口 3              [———————]
```

每个窗口是一个 8×14 的矩阵，标签取窗口**最后一秒**的标签（表示"到现在为止的 8 秒
反映出的状态"）。窗口**不跨段、不跨文件**，避免把两段不同任务拼进同一个样本。

### 4.5 第 5 步：分组切分与标准化

- **按会话文件分组切分**（`train_test_split` 的 group 版本）：同一位被试的同一段
  数据只会整体落在训练集或验证集，绝不会一半训练一半验证——否则相邻窗口
  高度相关，验证指标会严重虚高；
- 默认 80% / 20%，且**标准化参数只用训练集**计算（均值/标准差），再作用到验证集，
  防止信息泄漏；
- 报告用的性能来自**留一会话交叉验证**（`group_kfold` / `cv_sessions`）：每折完整留出
  一个会话，其余会话训练，8 个会话就是 8 折。只有 1 个会话时程序直接拒绝交叉验证
  （`ValueError`），避免"用同一段信号的相邻窗口当验证集"这种自欺欺人的数字。

### 4.6 数据集统计（合成数据，用于验证流程）

| 项目 | 数值 |
| --- | --- |
| 会话文件 | 4（S01–S04，每位 6 段 × 60 s） |
| 原始行数 | 4 × 360 = 1 440 |
| 有效窗口 | 965 |
| 切分 | 训练 751 / 验证 214 |
| 正样本比例 | 0.488 |
| 每样本形状 | 8 × 14 |

## 5. 模型设计

### 5.1 为什么是 1-D CNN

输入是一个 8×14 的"小图"：横轴是时间（8 秒），纵轴是特征。专注状态在时间上表现为
**一段持续的模式**（例如 beta 频段抬升、attention 缓慢上升），而不是某一秒的孤立数值。
1-D 卷积正好擅长捕捉这种**局部时间模式**：

- 卷积核在时间轴上滑动，同一组权重在 8 个位置上共享 → 参数极少；
- 3 层堆叠后，第 3 层的感受野覆盖完整的 8 秒，相当于"看完了整个窗口"；
- 相比 RNN/Transformer，卷积没有循环依赖，推理是一串定长矩阵乘，适合 MCU；
- 相比"把 8×14 拉平成 112 维喂全连接"，卷积保留了时间结构，参数量还少一个量级。

### 5.2 网络结构

| 层 | 配置 | 输出形状 | 参数量 |
| --- | --- | --- | --- |
| Conv1D-1 | 14→16，k=3，same padding，ReLU | 8×16 | 14×16×3 + 16 = 688 |
| Conv1D-2 | 16→20，k=3，ReLU | 8×20 | 16×20×3 + 20 = 980 |
| Conv1D-3 | 20→24，k=3，ReLU | 8×24 | 20×24×3 + 24 = 1 464 |
| GAP | 时间轴平均池化 | 24 | 0 |
| Dense | 24→1 | 1 | 25 |
| **合计** | | | **3 157** |

- **GAP（全局平均池化）** 代替 Flatten：让模型对"模式出现在窗口的哪个位置"不敏感，
  同时把参数量压到最低；
- 输出单个 logit，经 sigmoid 得到 P(专注)，阈值默认 0.5（界面可调）；
- 整个前向约 **24 600 次乘加**（≈49 kFLOPs），int8 权重约 **3.2 KB**。

### 5.3 训练细节

| 项目 | 设置 | 理由 |
| --- | --- | --- |
| 损失 | 带 logits 的二元交叉熵 | 数值稳定，不需要先 sigmoid |
| 优化器 | Adam（lr=1e-3，β=0.9/0.999，L2=1e-4） | 小模型收敛快，不需要调参 |
| 批大小 | 32 | 965 个样本 ≈ 24 步/轮 |
| 轮数 | ≤300，早停 patience=60 | 监控验证损失，恢复最优权重 |
| 数据增强 | 时间平移 ±2 帧 + 高斯噪声 σ=0.02 | 对抗小样本过拟合 |
| 初始化 | He 初始化 | 配合 ReLU |
| 随机种子 | 42 | 保证可复现 |

反向传播是**手写**的（`Conv1D.backward` 用 im2col + 矩阵乘），并用中心差分数值梯度
对全部 3 157 个参数做了校验：**余弦相似度 0.99976**，相对误差中位数 9.5e-4。
这一步保证"模型能学"不是靠框架，而是实现本身正确。

### 5.4 对照基线（brief 的 Option A）

设备厂商的常规做法：对 attention 做 3 秒滑动平均，超过阈值（75）判为专注。
本项目把它实现为 `threshold_baseline()`，与 CNN 在同一验证集上比较，
用来回答"深度学习到底有没有必要"。

## 6. 训练与评估流程（程序内如何跑）

```
选择原始 CSV（可多选）
   → build_dataset()      清洗 + 滑窗 → X (N,8,14), y (N,), groups, subjects, sources
   → split_dataset()      按 groups 分组切 80/20（单组时退化随机并明确报警）
   → standardize()        用训练集均值方差
   → train_cnn()          Adam + 早停 + 增强，init_state 可载入预训练权重
   → evaluate()           Accuracy / Precision / Recall / F1 / AUC / 混淆矩阵
   → threshold_baseline() 同一验证集上的对照（只在验证窗口上算）
   → save_model()         model.json（权重 + μ/σ + 指标 + 元信息）
   → export_edge_header() int8 量化的 C 头文件
```

四条训练路径（对应 ④ 页的四种模式）：

```
快速训练     run_training / train_from_dataset    留出 20% 会话，确认流程通不通
交叉验证     cv_sessions(folds=K, by="session")   每折留出一个会话，输出 mean±std
最终模型     fit_final(ds, init_state=…)          全部会话重训，轮数取 CV 最佳轮中位数
外部预训练   train_external()                     只用 data/external，产出初始化权重
```

界面第 ④ 页把上述每一步可视化：loss 曲线、混淆矩阵热图、五项指标、保存/导出按钮。
指标定义（正类 = 专注）：

- Accuracy = (TP+TN)/N
- Precision = TP/(TP+FP)，Recall = TP/(TP+FN)
- F1 = 2PR/(P+R)
- AUC = 用概率排序计算的 ROC 曲线下面积（不受阈值影响，衡量可分性）

## 7. 边缘部署

| 项目 | 数值 |
| --- | --- |
| 参数量 | 3 157 |
| int8 权重 | ≈3.2 KB |
| 单次推理 | ≈24.6 kMAC |
| 输入 | 8×14 int8（含 μ/σ 标准化参数） |
| 输出 | 1 个 logit → sigmoid |

程序里有两个导出路径：

1. `--export-tflite`：若安装了 TensorFlow，导出**全整型量化**的 `.tflite`
   （输入输出均为 int8，校准集用训练集），可直接喂给 TFLite Micro；
2. 默认导出 `models/model_int8.h`：把每层权重按 per-tensor 对称量化成 int8，
   连同 μ/σ 一起写成 C 数组，MCU 侧用几十行 C 就能完成前向——
   不依赖任何推理框架，适合课程演示"模型真的能塞进单片机"。

在 MCU 上，1 Hz 推理的算力需求可以忽略（24.6 kMAC ≈ 几十微秒 @100 MHz），
真正的瓶颈是**串口/蓝牙的 512 Hz 数据流**与内存（原始波形环形缓冲）。

## 8. 结果

### 8.1 合成数据上的结果（仅验证链路）

> 这张表的验证集是**同一批会话里随机抽的 20%**，相邻窗口共享 7/8 秒信号，
> 因此数字偏乐观，只能说明"链路通了、模型能学"。跨会话的真实水平看 8.3。

验证集 214 个样本（1 位被试整段留出）：

| 方法 | Accuracy | Precision | Recall | F1 | AUC |
| --- | --- | --- | --- | --- | --- |
| **3 层 1-D CNN** | **0.902** | **0.986** | 0.775 | **0.868** | **0.920** |
| 3 s 均值 + 阈值 75 | 0.679 | 0.633 | 0.815 | 0.712 | 0.745 |

混淆矩阵（行 = 真实，列 = 预测）：

|  | 预测静息 | 预测专注 |
| --- | --- | --- |
| **真实静息** | 124 | 1 |
| **真实专注** | 20 | 69 |

观察：

- CNN 的**精确率极高（0.986）**、召回率偏低（0.775）：它很少把静息误判成专注，
  但会漏掉一部分专注段。对"专注提醒"类应用，这是更安全的错误方向；
- 基线方法的召回率不低但误报严重（223 个静息被判成专注），说明固定阈值
  无法适应个体差异——这正是需要用学习方法的理由；
- 训练 62 轮后触发早停，训练损失降到 0.007 而验证损失升到 17，
  典型的**过拟合**：模型记住了被试特有的漂移。这也是第 9 节要讨论的主要风险。

### 8.3 留一会话交叉验证（合成数据）

用 4 个合成会话（965 窗，最多 120 轮，lr 10⁻³，seed 42）做 4 折留一会话
（`python main.py --cv 4 --epochs 120 --init {scratch,external}`）：

| 初始化 | Accuracy | F1 | AUC | 基线 acc |
| --- | --- | --- | --- | --- |
| 随机（scratch） | **0.798 ± 0.121** | **0.820 ± 0.055** | **0.864 ± 0.099** | 0.514 |
| 外部预训练（external） | 0.759 ± 0.164 | 0.781 ± 0.121 | 0.828 ± 0.224 | 0.514 |

逐折（scratch / external）：S04 0.902 / 0.794，S03 0.806 / 0.767，
S02 0.857 / 0.937，S01 0.627 / 0.539。

- **跨会话比同会话切分难得多**：8.1 的 0.902 是同一批会话内切 20%，换一个没见过的会话
  就掉到 0.77。这个 ~0.13 的差距就是 4.5 节所说泄漏的规模，也是"必须按会话划分"的直接证据。
- **单折最佳轮可能很靠前**（scratch 的第 4 折停在 1 轮，external 各折 5/34/32/23 轮）：验证损失在第一轮之后
  就不再下降，说明模型很快记住了训练会话特有的幅度尺度。因此最终模型的轮数设有
  3 轮下限（`epochs_from_cv`），避免"全部会话重训"被一折早停带偏。
- 外部预训练**单独**评估（留一性别 2 折，475 窗）：acc **0.918 ± 0.050**
  （留出 Male 0.953 / 留出 Female 0.883）。说明公开数据里"专注 / 非专注"的注意力量级
  确实可分；但迁移到 FP1 合成窗口没有收益，见 8.4。

### 8.4 两阶段训练与两个模型

**协议**：阶段 1 只用公开数据训练（`--pretrain`）得到初始化权重；阶段 2 用主数据训练，
分别以"随机初始化"和"预训练初始化"为起点各跑一遍，其余超参数完全相同。
两个模型结构、参数量、输入完全一致，唯一的差别是起点。

| 文件 | 训练数据 | 用途 | 是否交付 |
| --- | --- | --- | --- |
| `models/pretrained_external.json` | 160 个外部试次（475 窗） | 阶段 2 的初始化 | 中间产物 |
| `models/model.json` | 8 个主数据会话，外部初始化 | 两阶段模型 | **是**（候选） |
| `models/model_scratch.json` | 8 个主数据会话，随机初始化 | 从零训练模型 | **是**（候选） |

两个候选都交付，**最终采用哪个由下面这条规则决定**，而不是先挑一个再解释。

**选择规则（跑之前就定好）**：按留一会话交叉验证的均值选；两者差值小于 1 个标准差时
选 scratch（奥卡姆剃刀）。规则的目的是避免"看完结果再挑一个好看的"。

**本批合成数据上的结论**：0.798（scratch）vs 0.759（external），差值 0.039 远小于
1 个标准差（0.121）→ 按规则选 **scratch**。也就是说在合成数据上，外部预训练没有带来收益。
这不等于"外部数据没用"，原因有三条，写清楚比给一个漂亮的数字更重要：

1. **特征空间不一致**：外部数据只有 attention/meditation/8 段功率，没有 `raw_std`/`raw_max`。
   导入时补 0、训练时用主数据均值填充，这两维在外部预训练里等于常数，
   卷积核学不到它们的用法，微调时等于重新学。
2. **标签来源不同**：外部数据的标签来自目录名（Focus / Not Focus），而它是用厂商 attention
   阈值化出来的；本项目刻意不把 attention 当标签，两者的"专注"定义并不等价。
3. **主数据是合成的**：合成会话用高斯式频段功率模拟，与真实 EEG 的 1/f 结构差得远，
   外部权重在这里既帮不上忙也未必有害——这正是"负迁移 / 零迁移"要实测的原因。

因此这张表在真实采集完成后必须重跑，结论以真实数据为准；论文式报告里也应该
同时给出"从零训练"和"预训练微调"两列，而不是只报好的那个。

当前仓库里两个模型都保存了（`models/model.json` 与 `models/model_scratch.json`），
⑤ 页可以随时切换对比同一段实时信号在两个模型下的概率——这比只留一个模型更能说明
"差别只在初始化"。

## 9. 局限与挑战

| 挑战 | 具体表现 | 应对 |
| --- | --- | --- |
| **样本极少** | 3 段 × 60 s ≈ 每人 170 个窗口，1 位被试留出后只剩 3 人训练 | 数据增强、GAP 降参、早停、分组切分 |
| **个体差异大** | 同一模型换个人就掉点（合成数据里验证损失飙到 17 就是这个问题） | 每人单独校准（用本人 2 分钟静息数据微调阈值/标准化参数） |
| **标签噪声** | 被试"假装专注"、走神、心算中途卡住 | 两种状态都闭眼、不动手，避免眼动/肌电混入标签；段末报数写入 `*_tasks.csv` 留证；每段丢弃前 10 s；多段平均 |
| **伪迹** | 眨眼、咬牙、吞咽、头动都会污染 1 Hz 特征 | `signal` 阈值 + `raw_std` 的稳健 4σ 规则；采集结束时自动体检（`*_quality.txt`）提示两类状态的幅度/alpha 是否失衡；提醒被试少动 |
| **设备黑盒** | attention 由厂商算法给出，无法解释 | 只当特征不当标签；报告中明确其局限 |
| **1 Hz 分辨率** | 每秒才一个点，8 秒窗口只有 8 个时间步 | 窗口内加入差分特征；未来可把 512 Hz 原始波形降采样成 8×N 作为第二输入 |
| **过拟合** | 训练损失 →0，验证损失 →17 | 早停 + 增强 + 权重衰减；真实数据上应增加被试数而非堆模型 |
| **单通道** | 无法做空间滤波，眼电与脑电混在一起 | 电极位置固定在 FP1，靠协议控制行为；必要时加 ICA（需多通道） |
| **单会话泄漏** | 同一会话内切训练/验证，相邻窗口共享 7/8 秒，acc 可到 1.000；换会话就掉 0.13 | 按会话分组 + 留一会话交叉验证；单会话时程序拒绝交叉验证并明确报警 |
| **会话间漂移** | 每次重新贴电极，阻抗与基线不同；合成数据上跨会话比同会话低约 0.13 | 每会话单独做体检（`*_quality.txt`）；标准化参数只用训练集；报告给出 mean±std 而不是单次最好值 |
| **外部数据负迁移** | 公开数据缺 `raw_std`/`raw_max`，标签来自厂商 attention，特征空间与标签定义都不一致 | 外部数据只做初始化、不混训；用留一会话 CV 实测增益，差值 <1σ 时选 scratch |
| **采集成本** | 8 会话 × 8 分钟，加贴电极与休息约 2 小时 | 分两天采（每天 4 会话）；每次采完立刻看体检结论，告警就重采 |

## 10. 复现步骤

```bash
# 0. 环境
python -m pip install -r requirements.txt

# 1. 无硬件自检（协议 / 梯度 / 端到端）
python main.py --selftest

# 2. 合成数据跑通全链路
python main.py --make-demo
python main.py --train --epochs 300

# 3. 主数据采集（1 被试 × 8 会话 × 8 段）
python main.py --record --port COM7 --subject S01 --blocks 8 --block-sec 60
#    每次采完看 data/raw/*_quality.txt：告警的会话重采

# 4. 外部数据预训练（可选，用于两阶段对比）
python main.py --import-external "path/to/NeuroSky.zip"
python main.py --pretrain --epochs 200

# 5. 留一会话交叉验证（报告里的性能数字来自这里）
python main.py --cv 8 --init scratch
python main.py --cv 8 --init external

# 6. 用全部会话重训最终模型
python main.py --fit-final --init scratch
python main.py --fit-final --init external

# 7. 演示
python main.py      # ⑤ 实时推演 → 选 models/model.json 或 model_scratch.json → 看 P(专注)
```

每一步都有对应的界面入口：② 采集、③ 构建数据集、④ 训练、⑤ 推演。
